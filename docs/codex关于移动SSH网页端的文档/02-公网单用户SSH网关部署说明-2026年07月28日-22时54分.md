# 公网单用户 SSH 网关部署说明

## 业务边界

本方案面向“公网访问、仅一名管理员使用”的移动 SSH 场景。公网入口可以使用 Cloudflare Tunnel、Nginx 或 Caddy 提供 HTTPS/WSS，Node 网关保持监听 `127.0.0.1:5581`，不能将该端口直接映射到公网。

当前版本只支持 SSH 用户名和密码认证。它不包含多人权限、SSH 私钥、SFTP、跳板链，也不会修改 Electron 桌面端的鉴权。

## 部署前提

- 已安装项目依赖，并可在部署机执行 Node.js 服务。
- 已准备一个只用于本服务的域名，例如 `ssh.aizzj.cloud`。
- 域名已接入 Cloudflare Tunnel，或已解析到配置了 Nginx/Caddy 的部署机；任何方式都不开放 `5581`。
- 公网入口已配置有效的受信任 TLS 证书并支持 WebSocket。
- Node 服务用户对 `MOBILE_SSH_KNOWN_HOSTS_PATH` 的父目录具有读写权限。

## 构建移动页面

在项目根目录执行：

```bash
npm run mobile-web-build
```

构建结果位于 `work/mobile-web/`。网关启动时会检查其中是否存在 `index.html`。

## 生成管理员认证参数

交互生成管理员密码哈希，密码至少 12 位：

```bash
npm run mobile-ssh-password-hash
```

脚本不会回显输入内容，输出的完整 `scrypt$...` 字符串用于 `MOBILE_SSH_ADMIN_PASSWORD_HASH`。不要把管理员明文密码写入仓库、命令行参数或浏览器存储。

再生成至少 32 字符的 JWT 密钥，例如：

```bash
openssl rand -hex 32
```

JWT 密钥必须独立保存，修改后所有现有移动登录会话都会失效。

## 环境变量

生产环境至少配置以下变量：

```text
MOBILE_SSH_HOST=127.0.0.1
MOBILE_SSH_PORT=5581
MOBILE_SSH_PUBLIC_ORIGIN=https://ssh.aizzj.cloud
MOBILE_SSH_ADMIN_PASSWORD_HASH=scrypt$<salt>$<digest>
MOBILE_SSH_JWT_SECRET=<至少32字符的随机密钥>
MOBILE_SSH_ALLOWED_HOSTS=127.0.0.1,159.75.6.223,ssh.aizzj.cloud,207.56.229.202
MOBILE_SSH_KNOWN_HOSTS_PATH=/home/ubuntu/electerm-mobile-ssh/data/known_hosts
```

关键约束：

- `MOBILE_SSH_PUBLIC_ORIGIN` 必须与浏览器地址栏中的协议和域名完全一致，生产环境必须使用 `https://`。
- `MOBILE_SSH_ALLOWED_HOSTS` 是逗号分隔的 SSH 主机白名单。单人场景应逐台列出，不建议使用 `*`。
- 白名单按页面填写的主机字符串匹配；若同一主机同时使用 IP 和域名访问，需要把两者都列入白名单。
- `MOBILE_SSH_KNOWN_HOSTS_PATH` 用于持久保存已确认的 SSH 主机公钥，必须位于可持久化且仅服务用户可写的位置。
- `MOBILE_SSH_ALLOW_INSECURE_HTTP=yes` 仅供本机测试，生产环境不得配置。

建议把这些值放入仅服务用户可读的环境文件，并将权限设为 `0600`。环境文件和 `known_hosts` 不得提交到 Git。

## 启动网关

加载生产环境变量后，在项目根目录执行：

```bash
npm run mobile-ssh-server
```

正常日志应显示网关监听在：

```text
mobile SSH gateway listening on 127.0.0.1:5581
```

生产部署应使用现有的进程守护方式管理该命令，并确保工作目录为项目根目录。部署或升级前先执行移动页面构建；服务退出后，现有 SSH 会话会立即断开。

## Cloudflare Tunnel 配置

当前腾讯云部署复用了服务器现有隧道。在 `/home/ubuntu/.cloudflared/config.yml` 的最后一条兜底规则之前加入：

```yaml
  - hostname: ssh.aizzj.cloud
    service: http://127.0.0.1:5581
```

修改前先备份原配置，再执行：

```bash
cloudflared tunnel ingress validate
cloudflared tunnel route dns --overwrite-dns <tunnel-id> ssh.aizzj.cloud
sudo systemctl restart cloudflared.service
```

Cloudflare Tunnel 自动承载 HTTPS 和 WSS，服务器不需要为该域名直接监听公网 `80/443`。同一个配置中的兜底 `http_status:404` 必须保持为最后一条规则。

## Nginx 反向代理示例（替代方案）

下面配置让页面、API 和 WebSocket 共用同一 HTTPS 域名：

```nginx
server {
    listen 443 ssl http2;
    server_name ssh.aizzj.cloud;

    ssl_certificate /etc/letsencrypt/live/ssh.aizzj.cloud/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ssh.aizzj.cloud/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:5581;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

另行保留从 HTTP 到 HTTPS 的跳转配置。修改后先执行 `nginx -t`，确认通过再重载 Nginx。

## Caddy 反向代理示例（替代方案）

Caddy 会自动处理 TLS 和 WebSocket 升级：

```caddyfile
ssh.aizzj.cloud {
    reverse_proxy 127.0.0.1:5581
}
```

修改后先执行 `caddy validate --config /etc/caddy/Caddyfile`，确认通过再重载 Caddy。

Cloudflare Tunnel、Nginx 与 Caddy 三选一即可，不要同时维护多个正式公网入口。

## 首次使用与主机指纹

1. 用 iPhone Safari 打开正式 HTTPS 地址，输入移动网关管理员密码。
2. 新建 SSH 连接，填写白名单内的主机、端口、用户名和 SSH 密码。
3. 首次连接会显示 SSH 主机公钥指纹。通过服务器控制台或可信运维渠道核对指纹后，再点击“我已核对，信任此指纹”。
4. 确认后公钥会写入 `known_hosts`。以后主机公钥发生变化时必须重新核对，不能直接接受。
5. 进入终端后，轻触终端或点击“打开键盘”即可使用 iPhone 系统键盘；Ctrl、Esc、Tab 和方向键由页面快捷键栏补充。

移动页面只在本机浏览器存储最近连接的主机、端口和用户名，不保存 SSH 密码。登录凭证存放在 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie 中。

## iPhone 键盘输入优化

2026 年 7 月 29 日的前端更新针对 iPhone Safari 做了以下处理：终端输入框关闭自动大写、自动纠错、自动完成和拼写检查；“打开键盘”及快捷键按钮不会抢走终端输入焦点；页面 Ctrl 状态同时支持软键盘输入；键盘弹出时按可视视口直接调整页面高度，并合并终端重排与尺寸上报，避免终端区域反复增长或连续抖动。

公网逐字符回显仍取决于浏览器、Cloudflare Tunnel、腾讯云和目标 SSH 主机之间的往返时间。实测正式域名的逐字符回显中位数约为 `426.1ms`，服务器本机健康接口低于 `1ms`，因此前端优化可以减少额外重排、焦点丢失和重复尺寸消息，但不能消除公网链路时延。本版本没有加入本地终端回显，因为密码提示、Vim、tmux 等场景可能出现字符泄露、重复输入或显示错乱。

本次线上前端回滚点为 `/home/ubuntu/electerm-mobile-ssh-backup-20260729-keyboard-fix.tar.gz`。需要回退时，在服务器执行：

```bash
sudo systemctl stop electerm-mobile-ssh.service
tar -xzf /home/ubuntu/electerm-mobile-ssh-backup-20260729-keyboard-fix.tar.gz -C /home/ubuntu/electerm-mobile-ssh
sudo systemctl start electerm-mobile-ssh.service
```

## 上线检查

- 公网只能访问 `443`，不能直接访问 `5581`。
- `curl http://127.0.0.1:5581/api/mobile-ssh/health` 在部署机本地返回 `{"ok":true}`。
- 浏览器访问 `https://ssh.aizzj.cloud` 时证书有效，页面、登录、首次指纹确认和终端输入输出均正常。
- 非白名单主机连接被拒绝。
- 浏览器开发者工具中终端使用 `wss://ssh.aizzj.cloud/ws/mobile-ssh/...`，没有混合内容错误。
- 备份并保护 `known_hosts`；SSH 主机重装或公钥变化时先核对变更来源。

## 当前风险与限制

- 公网单密码入口仍会受到扫描和口令尝试，应使用长且唯一的管理员密码；内置限制为同一来源 15 分钟内最多 5 次失败登录。
- 当前管理员登录有效期为 8 小时，SSH 会话默认空闲 30 分钟后回收，同时最多保留 4 个活动会话。
- 当前版本没有二次验证。若需要进一步降低公网暴露面，应在反向代理前增加 VPN、Tailscale 或受控 IP 白名单，但这属于后续独立任务。
- SSH 认证目前只支持密码，密码只用于当前建链，不会写入最近连接记录。

## 回滚

1. 执行 `sudo systemctl disable --now electerm-mobile-ssh.service` 停止并禁用网关。
2. 将 `/home/ubuntu/.cloudflared/config.yml.before-electerm-mobile-ssh-20260728-2308` 恢复为 `/home/ubuntu/.cloudflared/config.yml`，执行 `cloudflared tunnel ingress validate` 后重启 `cloudflared.service`。
3. 在 Cloudflare DNS 中移除 `ssh.aizzj.cloud` 指向该隧道的 CNAME；不要改动 `hermes.aizzj.cloud` 路由。
4. 保留 `known_hosts` 作为审计或备份；确认无需恢复后再按运维规范处理，不要直接无备份删除。
5. 确认不再需要回滚数据后，再移除 `/etc/electerm-mobile-ssh.env`、`/etc/systemd/system/electerm-mobile-ssh.service` 和 `/home/ubuntu/electerm-mobile-ssh`；不要直接无备份删除。
6. 若要回退仓库实现，移除 `src/mobile-server/`、`src/mobile-web/`、`build/bin/mobile-ssh-password.js`、`build/vite/mobile-conf.js` 和移动 SSH 测试文件，并只撤销 `package.json` 中四个 `mobile-*` 脚本及对应移动 SSH 文档、进度记录。
