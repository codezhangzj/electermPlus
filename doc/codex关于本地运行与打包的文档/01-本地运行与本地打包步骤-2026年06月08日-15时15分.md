# electermPlus 本地运行与本地打包步骤

本文记录在本机从源码运行、以及使用一键脚本打包的推荐命令。当前本机环境为 macOS Apple Silicon，因此示例优先使用 `mac-arm` 和 `dir` 目标。

## 一、这次旧界面问题的结论

你执行的命令本身是正确的：

```bash
cd /Users/ai_project/electermPlus
./一键打包.sh --target mac-arm --clean-cache
```

但如果在同一个版本号 `3.15.35` 下反复安装，本地 Electron/Chromium 可能继续读取上一版缓存的静态资源。原来的生产资源文件名类似：

```text
js/basic-3.15.35.js
js/electerm-3.15.35.js
css/style-3.15.35.css
```

这些文件名只包含版本号，不包含代码内容指纹；而生产资源服务又设置了较长缓存时间。因此“安装包里可能已经有新代码，但运行时仍加载旧 JS/CSS”，看起来就像打出来的是旧包。

已经对构建流程做了缓存规避修复：正式构建会生成带 hash 的入口资源，例如：

```text
js/basic-3.15.35-jWPOA8N3.js
js/electerm-3.15.35-BkeAwgip.js
css/style-3.15.35-OnQAuWWo.css
```

后续同版本重新打包时，只要代码内容变化，文件名也会变化，安装后就不会继续命中旧入口资源缓存。

注意：`dist/electermPlus-3.15.35-mac-arm64.dmg` 如果是在本次缓存修复之前生成的，需要重新执行正式打包命令生成新的 DMG。

## 二、先确认当前代码

进入项目根目录：

```bash
cd /Users/ai_project/electermPlus
```

查看当前工作区是否包含你要打包的修改：

```bash
git status --short
```

如果要确认某个文件里的新代码是否存在，可以用：

```bash
grep -n "server-resource-modal" src/client/components/home-dashboard/home-dashboard.jsx
```

如果这里能看到新代码，但安装包里看不到，大概率是打包复用了旧构建产物，或者安装后打开的是旧应用实例。

## 三、本地运行步骤

本地开发运行需要两个终端窗口。

第一个终端启动 Vite 开发服务：

```bash
cd /Users/ai_project/electermPlus
npm start
```

看到类似下面输出说明前端开发服务已经起来：

```text
server started at http://127.0.0.1:5570
```

第二个终端启动 Electron 开发应用：

```bash
cd /Users/ai_project/electermPlus
npm run app
```

注意：如果系统里已经打开了 `/Applications/electerm.app`，开发版可能会受到单实例锁影响。为了准确看开发版效果，建议先手动退出已安装的 electerm，再执行 `npm run app`。

当前仓库没有单独的 `一键运行.sh`。本地运行就是上面的 `npm start` 和 `npm run app` 两个命令。

## 四、本地快速验包命令

如果只是想快速确认最新代码有没有进入打包产物，推荐先打未压缩目录包：

```bash
cd /Users/ai_project/electermPlus
./一键打包.sh --target dir --clean-cache
```

打包完成后查看产物目录：

```bash
ls -la dist
```

`dir` 目标不会生成正式安装包，通常会在 `dist/` 下生成未压缩应用目录，适合快速验证“是不是最新代码”。

## 五、本地正式 macOS Apple Silicon 打包命令

当前机器是 Apple Silicon，正式打本机 arm64 包推荐：

```bash
cd /Users/ai_project/electermPlus
./一键打包.sh --target mac-arm --clean-cache
```

如果你想让脚本按当前系统自动选择目标，也可以：

```bash
cd /Users/ai_project/electermPlus
./一键打包.sh --clean-cache
```

打包完成后查看安装包：

```bash
find dist -maxdepth 2 -type f -print
```

## 六、安装新版 DMG 前的建议动作

为了避免看到仍在运行的旧实例或旧缓存，安装新 DMG 前建议这样做：

```bash
pkill -f "electermPlus.app" || true
pkill -f "electerm.app" || true
```

然后从新生成的 DMG 安装 `/Applications/electermPlus.app`。安装后确认应用时间：

```bash
ls -ld /Applications/electermPlus.app
```

如果仍然看到旧首页，可以再手动退出应用，重新打开一次。缓存修复生效后，入口资源文件名会变化，正常不需要清理用户数据。

## 七、避免打到旧代码的关键点

不要在需要包含最新源码修改时使用：

```bash
./一键打包.sh --skip-build
```

原因是 `--skip-build` 会跳过 `npm run b`，复用已有的 `work/app`。如果 `work/app` 是之前生成的，那么打出来的包就会像旧代码。

推荐始终使用以下命令之一：

```bash
./一键打包.sh --target dir --clean-cache
```

或：

```bash
./一键打包.sh --target mac-arm --clean-cache
```

脚本内部会清理 `work/` 和 `dist/`，再执行 `npm run b`，然后重新准备 `work/app` 并打包。

## 八、打包前后的验证命令

打包前确认源码里有新组件：

```bash
grep -n "ServerResourceModal" src/client/components/home-dashboard/home-dashboard.jsx
```

打包后确认构建产物里也包含新组件相关代码：

```bash
grep -R "ServerResourceModal\\|server-resource-modal\\|服务器资源" work/app/assets | head
```

确认生产入口已经使用带 hash 的文件名：

```bash
grep -o "js/basic-[^\"]*\\.js\\|js/electerm-[^\"]*\\.js\\|css/style-[^\"]*\\.css" work/app/assets/index.html
```

正常应该能看到类似：

```text
css/style-3.15.35-xxxx.css
js/basic-3.15.35-xxxx.js
js/electerm-3.15.35-xxxx.js
```

如果源码里有、`work/app/assets` 里没有，说明构建步骤没有把最新代码编进去，需要重新运行：

```bash
./一键打包.sh --target dir --clean-cache
```

如果 `work/app/assets` 里有，但安装后的应用没有效果，请先完全退出已经打开的旧 electerm，再安装新包并重新打开。

如果要确认正式 macOS 包里的 `app.asar` 也已经带 hash 入口，可以运行：

```bash
node -e "const asar=require('@electron/asar'); const p='dist/mac-arm64/electermPlus.app/Contents/Resources/app.asar'; const html=asar.extractFile(p,'assets/index.html').toString('utf8'); console.log(html.match(/js\\/basic-[^\"]+\\.js|js\\/electerm-[^\"]+\\.js|css\\/style-[^\"]+\\.css/g))"
```

## 九、常用完整流程

推荐你本地按这个顺序执行：

```bash
cd /Users/ai_project/electermPlus
git status --short
grep -n "ServerResourceModal" src/client/components/home-dashboard/home-dashboard.jsx
./一键打包.sh --target dir --clean-cache
grep -R "ServerResourceModal\\|server-resource-modal\\|服务器资源" work/app/assets | head
```

确认快速验包没问题后，再打正式 arm64 包：

```bash
./一键打包.sh --target mac-arm --clean-cache
find dist -maxdepth 2 -type f -print
```

## 十、脚本参数简表

常用参数：

- `--target dir`：生成当前平台未压缩目录包，适合快速验包。
- `--target mac-arm`：生成 macOS Apple Silicon arm64 包。
- `--clean-cache`：清理本项目构建缓存，减少旧产物干扰。
- `--dry-run`：只演示流程，不真正安装、构建或打包。
- `--skip-install`：跳过 `npm install`。
- `--skip-lint`：跳过 `npm run lint`。
- `--skip-build`：跳过 `npm run b`，会复用旧 `work/app`，不建议用于验证最新代码。

需要先看脚本会做什么，可以运行：

```bash
./一键打包.sh --dry-run --target dir
```
